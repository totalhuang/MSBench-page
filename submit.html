Submit a model

Send us the videos your model generates for the MSBench scripts. We run the full evaluation with the same pipeline as every other entry, return the per-video scores to you, and add the model to the leaderboard in the next round.

1. Get the scripts

Download benchmark.json. It holds 300 scripts keyed by a hash ID: 125 at 4s, 125 at 8s and 50 at 15s (field duration_s).

Download benchmark.json

The main leaderboard uses the 4s + 8s scripts (250 videos). The 15s split is optional: submit it only if your model supports 15-second generation.

2. Generate one video per script

  • Prompt. Use the ready-made t2v_prompt string, or build your own input from the structured fields (global_context, entities_info, shot_sequence) if your model expects a different format, for example one prompt per shot or separate timing and camera arguments.
  • Keep the content. Reformatting is fine; changing what the script asks for is not. Shot order, time spans, camera angle / scale / movement, transitions, entities and scene descriptions must all be carried over.
  • Duration. Generate at the script's duration_s, or the closest length your model supports.
  • One sample, no selection. One video per script from a single run. Do not pick the best of several samples.
  • No manual editing. The video must come out of an automatic pipeline. A pipeline that generates shots separately and joins them automatically is allowed; describe it in the form.

3. Name and package the files

  • Name each file by the script's hash ID exactly as it appears in the JSON, including letter case: <hash>.mp4.
  • MP4 container, H.264 or H.265, at the model's native resolution and frame rate. Do not upscale, re-time or add overlays. Audio is ignored.
  • Put all files in one flat folder, with no sub-folders.
my_model/
├── 015faf665ba3c4264c491f63e07e8e0f.mp4
├── 0291226396e8190c133974cc59f9e24e.mp4
├── …
└── ff175a903ba6701a2d6490c276631655.mp4

4. Share the folder and fill in the form

Upload the folder to storage you control and create a share link, then choose whichever entry is easier to reach. Both go to the same queue.

The form asks for:

  • Model name and version, organisation, and a link to the paper, code or product page.
  • Whether the weights are open, and how the model obtains shot structure (single prompt, per-shot prompts, an agentic pipeline…).
  • Generation settings: resolution, frame rate, sampler and steps, seed policy, and how you built the input from the script.
  • The share link (and extraction code if any), valid for at least 30 days.
  • A contact e-mail. It is used only to send you results and is never published.

5. What happens next

  • Check. We verify that every expected file is present, readable and of the right duration. If something is missing we write to you before evaluating.
  • Evaluate. The videos are scored on all 11 sub-metrics. Evaluation uses GPU time and a hosted VLM judge, so submissions are processed in periodic rounds.
  • Publish. You receive the per-video scores first. The model is then added to the leaderboard with the settings you reported.

One entry per model version per round. Only videos are accepted; self-reported scores are not listed. We may decline submissions that do not follow the rules above, and we do not redistribute submitted videos without permission.
